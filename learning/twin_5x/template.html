Five Times the Reading

The same 7M twin trained twice from the same random start with the same recipe. The only change was the amount of text it read: 140M tokens on 7 Nov, 700M tokens on 11 Nov. Here both take the same locked exam, — held-out tokens they never trained on, and we look at where the extra reading helped, where it didn't, and why.

The scoreboard

Four players take the same exam. Score is bits per byte: how many yes/no questions the model needs, on average, to pin down each byte of the real text. Lower is better. "Untrained" is the twin's random start; "common words only" always guesses by how often each token appears.

Think about it
  1. Going from random to 140M tokens cut the score by 2.07. Going from 140M to 700M cut it by 0.06. Why is the second step so much smaller?

Where the gain came from

Kinds of token

A word start ("␣light"), the inside or end of a word ("ight"), punctuation, digits, spaces and line breaks.

How much context it had read

Surprise by position inside the 2,048-token window. Position 0 has no context at all; later positions can use everything before them. Both twins drop fast in the first ~60 tokens, then flatten: after a paragraph or so, more context stops helping them.

What did not improve

Copying test

A random string of 128 tokens shown twice. A model that can look back and copy finds the repeat easy (near 0). Both twins score worse than blind guessing on both halves, and the repeat barely helps.

first copyrepeatblind guessing

Looping

From 24 real held-out openings, each twin writes 80 tokens taking its top guess every time. Looping is the share of 4-token phrases it had already written earlier in the same answer.

Both twins loop on most answers. The extra reading didn't change that.
